Fundamentos de la Ingeniería de Software

Saber programar no es suficiente; saber organizarse lo es.

La Ingeniería de Software es la aplicación de un enfoque sistemático, disciplinado y cuantificable al desarrollo, operación y mantenimiento del software. Aporta las herramientas para planificar, diseñar y trabajar en equipo con metodologías reales.

El Paradigma del Desarrollo Profesional

El desarrollo empírico ("escribir código y probar") no escala en la industria. La Ingeniería de Software (IS) surge para mitigar riesgos, asegurar la calidad y garantizar que el producto cumpla con las expectativas del cliente en tiempo y forma.

El Mito del Código

Contrario a la creencia popular, la mayoría de los fracasos no se deben a la incompetencia técnica o errores de sintaxis, sino a problemas de gestión, mala comunicación y requerimientos ambiguos.

El Costo del Defecto (Shift-Left)

El costo de reparar un error crece exponencialmente. Un bug de diseño detectado en la etapa de análisis cuesta 1x. El mismo error descubierto en producción cuesta hasta 100 veces más.

El Ciclo de Vida del Software (SDLC)

El marco de referencia estándar (ISO/IEC/IEEE 12207) que define los procesos y actividades a lo largo de la vida de un sistema, independiente de si usamos modelo en Cascada o metodologías Ágiles.

🔍

1. Relevamiento

Ingeniería de requerimientos. Definir qué debe hacer el sistema resolviendo las necesidades del cliente.

📐

2. Análisis & Diseño

Modelado lógico y físico (UML). Arquitectura de datos, interfaces y reglas de seguridad.

💻

3. Implementación

Codificación aplicando buenas prácticas (Clean Code), control de versiones y estándares.

🧪

4. Pruebas (QA)

Verificación y validación. Pruebas unitarias, de integración y de aceptación del usuario.

🚀

5. Despliegue

Puesta en producción, monitoreo, mantenimiento evolutivo y correctivo del sistema.

📋

Ingeniería de Requerimientos

Base del alcance del proyecto. Un requerimiento es una condición o capacidad que debe poseer el sistema para satisfacer un contrato o estándar.

Requerimientos Funcionales (RF)

El QUÉ hace el sistema. Funciones específicas, comportamientos y cálculos.

Ej: "El sistema debe permitir al docente registrar la nota final del alumno."

Req. No Funcionales (RNF)

El CÓMO lo hace. Atributos de calidad: rendimiento, seguridad, usabilidad.

Ej: "El sistema debe encriptar las contraseñas usando SHA-256."
🖥

Modelado con UML

Lenguaje Unificado de Modelado. Es el estándar de la industria para visualizar, especificar y documentar los artefactos de un sistema.

  • ✓
    Diagramas de Casos de Uso Modela el comportamiento del sistema desde la perspectiva del usuario (Actores).
  • ✓
    Diagramas de Clases Modela la estructura estática, mostrando clases, atributos, métodos y sus relaciones lógicas.
  • ✓
    Diagramas de Actividad Flujogramas que muestran el flujo de control paso a paso para un proceso específico.
